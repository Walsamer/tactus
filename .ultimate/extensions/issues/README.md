The open GitHub issues of `Walsamer/tactus` in the right panel's Issues tab: what each one is, how far its acceptance criteria went, and one click that hands it to @ultimate with the rules to work by.

This project's open work lives as issues on GitHub; `docs/ROADMAP.md` is only a snapshot. The panel reads them on the server with `gh issue list --repo Walsamer/tactus --state open --limit 100 --json number,title,labels,milestone,body,updatedAt,url` (`server.ts`), so no token reaches the browser:

- **Grouped by milestone** (M0 first, no milestone last), the newest work first inside a group. Each issue shows its number and title, the labels that matter (`type:*`, `area:*`, `priority:*`, `fleet:*`, with `fleet:ready`, `fleet:human` and `fleet:blocked` toned apart), how many of the `## Acceptance criteria` checklist are ticked, and when it last moved; the arrow opens it on GitHub. The header counts the open issues and the ticked criteria overall and per milestone; the arrow there reads `gh` again.
- **The action follows the gate.** `start` hands the issue to @ultimate as one prepared prompt: the issue, its URL, milestone, labels, every acceptance criterion and the project's own hard rules (read from `AGENTS.md` at that moment), then `api.submit(text, 'followUp', id)` sends it to @ultimate's conversation and shows that conversation, so you watch it land. Only `fleet:ready` authorizes intake in this project, and `fleet:blocked`/`fleet:human` withdraw it (`src/tactus/domain/work_source.py`), so an issue with no `fleet:` label or a gated one reads `assess`: the button and `gate.ts` say so together, and the prompt asks @ultimate to say what has to change first instead of implementing. Everything the issue says is fenced in the prompt as data, not as instructions.
- @ultimate's conversation comes from the `ultimate.standing-agents` document on the root; when it does not name one yet, the `subagents` `standing` action resolves it. If neither works, the prompt is copied to the clipboard with a notice.
- A listing is cached for a minute and a setup failure is never cached. When `gh` is missing, logged out, or cannot see the repository, the panel says which and offers the command to copy. At most 100 issues are read, newest first.

Actions: `list` (no arguments → `{ status: 'ok', repo, fetchedAt, issues }` or `{ status: 'setup', reason, detail }`), `refresh` (same, read again), `prompt` (an issue number → the prompt string). `types.ts` holds the shapes both facets share.
